# I001 — Name conforms to MathComp grammar, or carries a `Naming:` justification

## Rationale

MathComp lemma grammar is `(condition_)?mainSymbol_suffixes(_condition)?`.
AI-authored proofs often drift into pure snake_case or generic names
(`my_proof_works`, `helper_tmp`, `schreier_gen_count_table`). The
operator wants a hard gate: either the name conforms, or the author
explicitly acknowledges the deviation in the preceding comment.

## What is audited

Names of the following declarations in the staged diff:

- `Lemma`, `Theorem`, `Fact`, `Corollary`, `Proposition`
- `Definition`, `Fixpoint`, `CoFixpoint`, `Let` (module-local)
- `Hypothesis`, `Variable`
- `let <name> := ... in ...` bindings inside proof bodies and definitional
  terms

## Non-conformance signals

A name triggers I001 when any of the following holds and the preceding
comment does not carry a `Naming:` tag:

1. Name ends with `_lemma`, `_theorem`, `_fact`, `_corollary`,
   `_proposition`, `_proof`, `_thm` (redundant: the declaration kind
   already says so).
2. Name contains a generic drift token: `_works`, `_test`, `_tmp`,
   `_old`, `_new`, `_foo`, `_bar`, `_baz`, `_placeholder`, `_helper`,
   `_helper1`, `_helper2`, `_xxx`, `_hack`.
3. Name has five or more underscore-separated components and does not
   end with a canonical suffix (see AUTHORITY.md suffix table).

## Justification format

To accept a non-conforming name, the preceding comment must contain a
line whose content begins with `Naming:` (case-insensitive) followed by
a short reason. Example:

```
(** schreier_gen_count_table — cardinality of the Schreier coset table.
    Kind: helper.
    Why: consumed by schreier_gen_count_ge0.
    Used by: schreier_gen_count_ge0.
    Naming: intentional; `table` mirrors the external reference. *)
Definition schreier_gen_count_table : nat := ...
```

For local `let <name> :=` bindings the comment can live either:

- Inline on the `let` line: `let tmp_x := ... in (* Naming: tmp is a
  throwaway *) ...`, or
- In the enclosing entity's preceding comment, with a line
  `Naming: <name> is intentional; <reason>`.

## Stages

- Stage 1 only. `fast_check: naming_conformance_or_justify` runs the
  check per entity after Tier 0 extraction.

## Bad

```coq
Lemma my_proof_works : forall n : nat, 0 < n.+1.
Proof. by []. Qed.

Definition schreier_gen_count_table : nat := 42.

Lemma foo : True.
Proof.
let helper_tmp := I in
exact: helper_tmp.
Qed.
```

## Good

```coq
(** ord_pos_ge0 — 0 is less than n.+1 for every n : nat.
    Kind: main. *)
Lemma ord_pos_ge0 : forall n : nat, 0 < n.+1.
Proof. by []. Qed.

(** my_proof_works — same content as ord_pos_ge0 but kept to match
    external reference module.
    Kind: helper.
    Why: referenced by tests that import the external module.
    Used by: ord_pos_ge0_test.
    Naming: intentional; the name mirrors the Python reference module. *)
Lemma my_proof_works : forall n : nat, 0 < n.+1.
Proof. by []. Qed.
```

## Known false-positive patterns

- Well-known Infotheo helper names that predate the audit and have been
  reviewed. Add them to the rule's `exceptions` list if they recur.
