# H001 — Declaration lacks a required role tag

## Rationale

Every in-scope declaration must carry exactly one role tag in its preceding
comment block: `@intent: ...` for a Definition or Fixpoint, `@composes:
<lemma>` for a helper lemma, or `@main <label>: ...` for a main result. H001
fires at `error` severity when no such tag is found.

## Migration grandfathering

When a legacy entity (not newly declared in the current diff) already has a
substantive comment but no tag, H001 fires at `warning` severity instead of
`error`. This allows incremental adoption: add a role tag on the next edit.
An entity whose declaration header was touched in the current diff is never
grandfathered and fires `error` even when a legacy comment is present.
A degenerate comment (empty, `TODO`, fewer than ten characters, or fewer than
two alphabetic tokens) is never grandfathered and fires `error` regardless.

## Targeting

- Always: `Lemma`, `Theorem`, `Fact`, `Corollary`, `Proposition`.
- `Definition` and `Fixpoint` only when body spans at least two lines, the
  declaration is not `Local`, and the right-hand side is not a single token.
- Out of scope: `Notation`, `Coercion`, `Canonical`, `Instance`,
  `HB.instance`, `Variable`, `Hypothesis`, `Axiom`, `Parameter`.

## Grace period

Controlled by `strict_comment_coverage` in `.claude/audit/config.yaml`.
Default `false`: an entity is audited when its declaration line **or any of its
body lines** is in the staged diff. A body-only change therefore surfaces a
pre-existing entity so the migration grandfathering can apply (substantive legacy
comment yields a `warning`; a header-touched or degenerate case yields `error`).
Set to `true` to audit every entity in every touched file.
