# A002 — `f_equal` is non-idiomatic; prefer goal-level `congr` (`congr1` is only a fallback)

## Rationale

`f_equal` is a Coq built-in that decomposes `f x1 .. xn = f y1 .. yn` into the
`xi = yi` subgoals. SSReflect's **goal-level `congr` tactic** is the
principled replacement: one call `congr <head>` discharges every argument of
the head symbol at once, lets a shared rewrite preamble close whole groups of
subgoals, and interacts cleanly with views. In MathComp code bases `f_equal`
is either a historical artifact or a sign that the author did not reach for
the right congruence lemma (`eq_big`, `eq_map`, `eq_ffun`, `congr_bigr`, …).

The term-level siblings `congr1`, `congr2`, `congr3`, `congr_dep` are
**aliases** for `f_equal`, `f_equal2`, `f_equal3`, `f_equal_dep` (literally
`Definition congr1 := @f_equal` in `ssrfun`). They satisfy the regex but
realise none of the rule's compression benefit. They are accepted only as a
**fallback** for cases where goal-level restructuring is genuinely
infeasible, and only when the fix carries a written justification that
goal-level `congr` was considered and ruled out. A bare `congr1` use with
no surrounding justification is a latent A002 finding.

## Stages

- Stage 1 fires on any declaration-adjacent occurrence of `f_equal`,
  `f_equal2`, `f_equal3`, or `f_equal_dep` outside a comment. The
  preceding-character class `(^|[ \t;(/,])` lets the regex match tactic
  form, view form (`/(f_equal f)`), and call-site forms (`(f_equal g)`,
  `,f_equal h`) while still rejecting identifier substrings such as
  `my_f_equal_lemma`.
- Stage 2 judges whether a goal-level `congr <head>` restructuring is
  feasible. If yes, it is the required fix. `congr1` (and siblings) are
  accepted only as a named fallback and only when the explanation records
  why goal-level `congr` does not apply.

## Bad

```coq
move=> a b eq_ab.
f_equal.
exact: eq_ab.
```

```coq
move=> /(f_equal (fun z => z - c)); rewrite addrC addrK.
```

```coq
apply: f_equal2.
```

## Good — canonical (goal-level `congr`)

```coq
move=> a b eq_ab.
congr S.
exact: eq_ab.
```

```coq
(* starting goal after a preceding rewrite: z - c = z' - c *)
rewrite Hxy; congr (_ - c).
```

Using a more specific congruence lemma:

```coq
apply: eq_big => // i _.
```

## Good — fallback (`congr1` alias, requires justification)

Accept `congr1` only when the goal cannot be set up to host `congr`.
Typical justification:

- the equality is produced by an opaque library lemma whose statement cannot
  be hoisted without duplicating the proof,
- dependent types prevent `congr` from elaborating,
- or the head symbol is not a matchable pattern.

The fallback must carry the reason inline, so a reviewer can see the
ruling-out of goal-level `congr` without re-deriving it:

```coq
(* Fallback: cardsC is an opaque library hypothesis; goal-level `congr`
   would require duplicating its statement. *)
move=> /(congr1 (fun z => z - c)); rewrite addrC addrK.
```

A bare `congr1` use with no `(* Fallback: ... *)` justification is a latent
A002 finding even though it passes the regex.

## Known false-positive patterns

- Identifiers containing `f_equal` as a substring (`my_f_equal_lemma`,
  `f_equal_tac`). The preceding-character class `(^|[ \t;(/,])` rejects
  these because `_` does not appear in the class.
- `Check f_equal.` or `About f_equal.` probes. These are rare and acceptable
  to flag; rewrite as `About congr.` if you want to check the idiom.
