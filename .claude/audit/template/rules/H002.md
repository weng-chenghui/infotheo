# H002 — Comment uses rigid template slots, embeds stale cross-references, restates the type, or exceeds the prose budget

## Rationale

A comment that ceremoniously stacks `Kind:` / `Why:` / `Used by:` slots
is lower-signal-per-line than a short prose comment that states the
entity's conceptual role or the proof's key trick. Templates also tend
to bring along plan-task tokens (`T4`, `U2`, `W3`), absolute line
numbers, and `[identifier]` brackets — all of which go stale and add no
information beyond what the type signature and surrounding code already
say.

H002 enforces the prose convention defined in AUTHORITY.md by flagging
four mechanical violation patterns. The intent is reader experience:
comments should be readable as prose, not as a filled-in form.

## Stages

- **Stage 2 only.** The detectors require reading prose patterns and
  comparing against the entity's type signature; Stage 1 only handles
  presence/absence.

## The four detectors

1. **TEMPLATE_SLOTS** — two or more of `Kind:` / `Why:` / `Used by:`
   on separate stacked lines. `Naming:` is NOT counted (it is the
   prescribed justification slot for F001/G001-flagged names; see
   AUTHORITY.md naming section).

2. **STALE_CROSSREF** — plan-file paths, absolute line numbers, and
   plan-task tokens in task contexts. The plan-task detector matches
   `\b[TUVW][0-9]+\b` only when preceded by "per/implements/closes/
   Task/task" or followed by a colon, to avoid false-positives on
   math symbols (`V2`, `U3`, `R3`, `D2`, `VU3R`, `T0`, etc.) that
   appear in legitimate prose.

3. **TYPE_RESTATEMENT** — the comment's first sentence overlaps ≥ 70%
   in content tokens with the entity's type signature. A crisp
   re-paraphrase is acceptable; a near-duplication of the type is not.

4. **OVER_LENGTH** — 8 lines for Lemma/Theorem/Fact/Corollary/
   Proposition, 25 lines for Hypothesis/Variable, 15 lines for
   non-Local multi-line Definition/Fixpoint.

5. **MECHANISM_ONLY** — the first 200 chars contain a proof-mechanism
   stop-phrase (`reduces to`, `by case analysis`, `discharges`,
   `obligations`, `by reflexivity`, `cancellation bijection`, …)
   AND fewer than 2 architecture/purposive nouns (`bridge`,
   `adversary`, `predictor`, `package`, `chain`, `game`, `space`,
   `AHE`, `SSProve`, `IND-CPA`, `secrecy`, …). The detector is
   "inverted": fires only when the comment is BOTH mechanism-
   anchored AND purposive-noun-poor, so prose that mentions a proof
   tactic alongside architectural framing (e.g., "Bijection
   bridging X and Y. The proof reduces to enum_rankK") does NOT
   fire. See AUTHORITY.md "Purposive framing first" for the full
   list and the three-tier example.

## Bad examples

```coq
(** chcipher_of_cipherK - cancel law for the ciphertext-side
    bijection.  Routes through [eq_rect] cancellation on the
    [cipher_finType_eq] cast plus [enum_rankK].
    Kind: cancellation.
    Why: discharges [chcipher_of_cipherK] (line 130).
    Used by: T1 V_2-aware rebuild. *)
Lemma chcipher_of_cipherK : cancel chcipher_of_cipher cipher_of_chcipher.
```

Violations: TEMPLATE_SLOTS (3 stacked slot lines); STALE_CROSSREF
(`T1`, `(line 130)`); TYPE_RESTATEMENT (first sentence paraphrases the
type); OVER_LENGTH (7 lines, budget 5).

```coq
(** card_t_msg - cardinality index used by [dsdp_alice_secrecy]'s
    residual bound [1 / card_t_msg].
    Kind: concrete-carrier index.
    Why: discharges [dsdp_security_indcpa]'s abstract [card_t_msg]
    section parameter at the concrete carriers so the closed-form
    bound numerically reads [1 / #|plain AHE| + 2 * epsilon_cpa].
    Used by: random_guess_adv, secrecy_random_guess. *)
Definition card_t_msg : nat := card_msg.
```

Violations: TEMPLATE_SLOTS (3 stacked slots); OVER_LENGTH (7 lines,
within the Definition budget but still ceremony).

```coq
(* The proof reduces directly to enum_rankK. *)
Lemma mechanism_only_example : forall n : nat, n = n.
```

Violations: MECHANISM_ONLY (mechanism anchor "reduces directly"; zero
architecture nouns in the first 200 chars). Pure mechanism-only prose
with no architectural framing.

## Good examples

```coq
(* Bijection to build type bridge between AHE and SSProve. *)
Lemma chmsg_of_msgK :
  cancel chmsg_of_msg msg_of_chmsg.
Proof. exact: enum_rankK. Qed.
```

```coq
(* For every predictor in the considered class, the probability that
   the predictor correctly guesses V_2 from the leaked-ciphertext
   game is at most 1 / card_t_msg.
   (distr.mu is the probability mass function of a sub-distribution;
    SSProve uses sub-distribution since its relative monad of
    sub-distributions on choice_type.) *)
Hypothesis Pr_guess_enc_zero_le_invm :
  forall (predictor : predictor_guesser t_msg t_cipher), ...
```

```coq
(* card_t_msg and card_msg are different at the abstract level
   (card_msg = #|plain AHE|, card_t_msg = size of the predictor's
   guess space). At all concrete instances we identify them; the
   positivity transfers via card_msg_gt0. *)
Definition card_t_msg : nat := card_msg.
```

These read as prose, focus on the conceptual role or proof trick, do
not stack template slots, do not cite plan files or task IDs, and stay
within the 5-line (Lemma) / 10-line (Definition) budget.
