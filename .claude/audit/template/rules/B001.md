# B001 — Verbose `boolP`-based eq-or-not split

## Rationale

The MathComp idiom for case-splitting on `X = Y` versus `X <> Y` is
`case: (eqVneq X Y) => h`, which produces two subgoals with `h : X = Y` and
`h : X != Y` respectively. The roundabout form
`have [/eqP h|h] := boolP (X == Y).` applies `boolP` to decide the boolean
equality, then views it through `eqP`, which is longer, uses `have` where
`case:` is more idiomatic, and does not advertise the semantics as clearly.

## Stages

- Stage 1 fires when a staged line contains `have [ /eqP`. Whitespace is
  permitted, so this also matches `have[/eqP` and similar.

## Bad

```coq
have [/eqP dst2i|dst2i] := boolP (dst2 == nat_of_ord i).
```

## Good

```coq
case: (eqVneq dst2 (nat_of_ord i)) => dst2i.
```

## Known false-positive patterns

- `have [/eqP ...]` applied to something that is not an `_ == _` expression.
  These are rare; when they do occur, rewriting to `case: ...` tends to be a
  clarity win anyway.
