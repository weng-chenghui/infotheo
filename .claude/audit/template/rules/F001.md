# F001 — Name does not follow MathComp grammar

## Rationale

MathComp's lemma grammar is `(condition_)?mainSymbol_suffixes(_condition)?`.
Names such as `schreier_transition_entry_ge0` are drifting toward generic
snake_case and tend to obscure the main symbol. Common clarifying
restructures:

- Pick a main symbol: `schreierTransition` or `schreier_transition`.
- Use a suffix from the authoritative list (see AUTHORITY.md): `_ge0`,
  `_le0`, `_eq0`, `_inj`, `_card`, `_E`, `_P`.
- Drop redundant connectives such as `_entry_` that do not describe the
  suffix.

Stage 1 flags the shape `^[a-z][a-z0-9]*(?:_[a-z0-9]+){2,}` on declaration
lines. This is a deliberately narrow trigger: three or more underscore
components in a pure-lowercase identifier. It is a heuristic; false
positives are expected and the real work happens in Stage 2 (rule G001).

## Exceptions

Lines beginning with `in_`, `mem_`, `card_`, or containing `_of_` are
common, legitimate MathComp patterns and are allowlisted.

## Bad

```coq
Lemma schreier_transition_entry_ge0 : ...
```

```coq
Definition schreier_gen_count_table : ...
```

## Good

```coq
Lemma schreier_transition_ge0 : ...
```

```coq
Definition schreierGenCount : ...
```

Or, when the name has a legitimate condition clause:

```coq
Lemma card_schreier_neq0_if_transitive : ...
```

(`card_` is allowlisted.)

## Known false-positive patterns

- Names such as `card_leq_card_preim` where each underscore component is a
  main-symbol. These are often legal. Consider adding them to the rule
  `exceptions` list if they recur.
