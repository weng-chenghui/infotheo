# G001 — Suffix does not match semantic role

## Rationale

MathComp lemma names are `mainSymbol_suffixes(_condition)?` where the
suffix signals the theorem's semantic role. Mismatches confuse library
users who search by suffix convention.

## Stages

- Stage 2 only. Classifying a theorem's role requires reading the
  statement and mapping it to the suffix table in AUTHORITY.md.

## Bad

```coq
Lemma fooP : my_lhs = my_rhs.       (* statement is an equation; should be foo_E *)

Lemma schreier_gen_count_lemma : ...  (* _lemma suffix is redundant *)
```

## Good

```coq
Lemma foo_E : my_lhs = my_rhs.

Lemma schreier_gen_count : ...
```

## Suffix-role table (short version, full table in AUTHORITY.md)

| Role | Suffix |
|---|---|
| Reflection / property | `P` |
| Equation / rewrite | `E` |
| Injectivity | `I` |
| Non-negative | `_ge0` |
| Cardinality | `_card` |
| Associativity | `A` |
| Commutativity | `C` |
| Weak monotony | `w` |
| Zero / unit | `0`, `1` |

## Known false-positive patterns

- `Lemma foo_E` where `_E` is part of a main symbol like `_Enc`. Rare;
  when confirmed, add the name to `G001.exceptions`.
