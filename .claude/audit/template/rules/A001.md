# A001 — `pose proof` is non-idiomatic; prefer `have`

## Rationale

MathComp's SSReflect proof language treats forward reasoning through `have`.
`pose proof` is a vanilla-Coq Ltac1 tactic that predates SSReflect's view
infrastructure and does not compose with `move/`, `move=>`, or `apply:` in the
same way. In an Infotheo-style codebase, the entire proof flow is SSReflect,
so a stray `pose proof` is visibly out of place and blocks readers who expect
the SSReflect idiom.

## Stages

- Stage 1 fires on any staged line matching `^\s*pose proof\b`.
- No Stage 2 component: the literal is unambiguous.

## Bad

```coq
pose proof XE_neq0 as EX_neq0.
move/(_ a b) in EX_neq0.
```

## Good

```coq
have EX_neq0 := XE_neq0 a b.
```

Or if the hypothesis is already specialised:

```coq
have EX_neq0 : P a b := XE_neq0 a b.
```

## Known false-positive patterns

- Comments and string literals containing the phrase `pose proof`. Handled by
  `ignore_in_comments: true`.
